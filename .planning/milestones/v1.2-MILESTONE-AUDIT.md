## Tech Debt

### Phase 18: Configuration Foundation

- **Advisory:** `submit-confirm.astro` renderPreview uses hardcoded `'2026-06-06'`/`'2026-06-07'` in display logic (lines 138, 140, 182, 219). These are UI labels for the score preview, not validation gates. Low risk — would only matter if event dates change.

### Phase 19: Fetch Pipeline Validation Gates

- **Advisory:** `distanceMeters` and `startDate` are transported through submit-confirm hidden fields but dropped from the submit-result POST payload. Not persisted in athlete JSON. This is non-blocking because validation fires at fetch time (before data reaches confirmation), but the fields could be useful for future audit trails.
- **Info:** `strava-fetch-activity.js` success return uses `undefined` instead of `{}` in multiValueHeaders spread (line 273). Functionally identical — undefined properties are ignored in object spread.
- **Minor:** `strava_api_error` code from strava-fetch-activity.js falls through to the generic error handler in submit.astro. Acceptable degradation — the generic message is appropriate.

### Total: 4 items across 2 phases (0 blockers, 4 advisory/info)
